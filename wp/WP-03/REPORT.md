How it works (one mechanism): `"color": {"linear_light": true, "working_profile": "srgb|display_p3", "space": "srgb|display_p3"}` on a
composition. Pictures are tagged with a Skia colour space, so Skia converts on every draw (unpremultiply, convert, premultiply);
alpha is never encoded. An untagged surface means no conversion, so a film without the key tags nothing and runs the exact code path
it ran before. Effects declare `display` or `linear` (a registry column for built-ins, `// @space display|linear` for plugins) and
run in that encoding through Skia's working-colour-space wrap, with no extra pass. Images are decoded tagged with their embedded
profile, video with its probed primaries and transfer; the finished frame is converted to the output profile and the file is tagged
with it. Spec and numbers: `parity/specs/colour_pipeline.md`.

Acceptance numbers (red channel, 8-bit; GPU unless "CPU"):
- sRGB <-> linear round trip over all 256 levels (CPU raster): curve error 0.00022 (bound 3e-4), round trip worst 0.019 of a level (bound 0.05). The CPU raster approximates the power function; GPU is exact to 1 level.
- 50% white over black: 188 in linear light (physical 187.5), 128 default.
- Add of two #808080: 176 in linear light (physical 175.6), 255 default.
- Blur (radius 6) of a hard black/white edge, the two pixels beside the edge: 181 / 192 in linear light (mean 186.5, light mean 0.495), 118 / 135 default (mean 126.5). The linear result is 60 levels brighter.
- Gradient 0..255 over 256 px: worst deviation from the ideal ramp 0.56 level in linear light (max step 12 vs ideal 11.1), 0.50 default; no band wider than the ideal step.
- Contrast (display-referred effect) is 64 in both modes; luma matte reads 188 in light mode and 128 default (same brightness the eye sees).
- Plugin doubling a grey: 255 declared `display`, 176 declared `linear`. A colour parameter arrives as 128 in the encoding the plugin declares.
- Premultiplication round trip: alpha 0.500 stays 0.500.
- P3: sRGB red leaving as P3 is (234, 51, 35); a P3 PNG with (255, 0, 0) in a P3 film stays (255, 0, 0); P3 red in sRGB linear is (1.0930, -0.2267, -0.1501).
- Determinism: two renders of the probe give the same shasum (see gate 6).

Deviations from this plan:
- The plan says the graph wraps linear effects with conversions. I use Skia's colour management instead (surfaces tagged with a colour space, `with_working_color_space` on the effect's shader or filter), which converts exactly where a draw happens, needs no extra pass and keeps the default path untouched. One mechanism, no parallel converter.
- Images are decoded tagged with their profile and converted by Skia on draw, not converted to half-float at import: less memory, mipmaps stay 8-bit. Colours inside the sRGB gamut are unchanged by this.
- Luma mattes, luma bands and lighting are display-referred (they read the brightness the eye sees); mesh shading is display-referred and drawn into a tagged surface. Stated in the spec and the catalogue.
- `depth` has the single value `half`: it is what the engine always used. 32-bit float is not offered.
- The old ledger row "Colour management" is renamed "Colour management beyond P3: Rec.2020 working space, HDR (PQ/HLG), 32-bit float depth, ICC and LUT display management" (`none`, WP-50) so no unbuilt claim is hidden; five `done` rows replace it (linear-light compositing; working profile and import conversion; output colour tagging; effect/plugin colour contract; premultiplication rules), each citing the spec, a test and the generated doc.
- `parity check` gains a check that each ledger `linear` cell matches the catalogue's `space` (91 cells filled in `effects.tsv`), mirroring the existing `grows_bounds` check.
- `Primaries` also lists Rec.2020, BT.470BG and SMPTE 170M, which exist to read video tags; the output and working gamuts a film can choose are `srgb` and `display_p3`.
- New code lives in new modules; code moved out of `fxlib/mod.rs` (730 -> 547), `render/mod.rs` (339 -> 247), `plan/mod.rs` (460 -> 432) and `schema/mod.rs` (501 -> 493) to keep them from growing; `eval/mod.rs` and `check/lint.rs` are untouched. `render/mod.rs` is now under 300 lines; the others were over before this WP and are smaller or equal after it.
- `core/src/color.rs` was replaced by a `color/` directory (the old file was deleted, not left behind).
- Video RGB-to-YUV: the encoder is told BT.709 and tags the file only when the film is managed; unmanaged films keep the previous (untagged) encode byte for byte.
- Display-referred effects stay `display` until ported: of the 91 `linear` cells filled in `parity/effects.tsv`, 17 are `yes` and 74 are `no`; the other 173 rows are future work and stay `?`.
- `scripts/capability_index.py` indexes the new `color` comp key (`scripts/capability_sdk.py` was not touched).
